# Smart Horizon Labs

**Open-source engineering for secure, intelligent, and interoperable systems.**

Smart Horizon Labs is the open-source engineering initiative of [Smart Horizon Consulting](https://smarthorizon.com.br).

We develop tools, protocols, and reusable components for organizations working with digital transformation, information security, artificial intelligence, decision automation, and public-sector innovation.

## What we work on

Our projects focus primarily on:

* **Privacy and applied cryptography**
  Client-side encryption, zero-knowledge architectures, secure collaboration, and privacy-preserving protocols.

* **Artificial intelligence agents**
  Reusable components and architectures for building reliable, auditable, and context-aware AI agents.

* **Decision and process automation**
  Standards-based tools for business rules, decision models, organizational processes, and public-policy implementation.

* **Data and digital infrastructure**
  Open components for information management, interoperability, analytics, and secure digital services.

* **Responsible technology**
  Practical approaches to security, predictability, transparency, governance, and human oversight.

## Projects

### `GroupVault`

A protocol for encrypted group vaults with membership changes, key rotation, access revocation, and secure state transitions.

The protocol is designed to support applications in which the storage backend can remain largely unaware of the contents it stores.

### `CircleKey`

A client-side cryptography library for applications that need secure group collaboration and encrypted data management.

CircleKey is our reference implementation of the GroupVault protocol.

### `dmn-runtime`

A standalone TypeScript runtime for executing **Decision Model and Notation — DMN** models.



## Engineering principles

Our open-source work follows a few core principles:

### Secure by design

Security and privacy should be architectural properties, not features added after implementation.

### Minimal trusted infrastructure

Whenever possible, servers and infrastructure components should require access to as little sensitive information as possible.

### Standards before proprietary formats

We prefer established and openly documented standards when they provide a suitable foundation.

### Predictable behavior

Systems that influence organizational or public decisions should be testable, observable, and explicit about their limitations.

### Reusable foundations

We build libraries and components that can be adopted independently, extended by other developers, and integrated into different technology stacks.

### Documentation as part of the product

Architecture, security assumptions, threat models, examples, and operational guidance are essential parts of our projects.

Before contributing, please read the `CONTRIBUTING.md` and `CODE_OF_CONDUCT.md` files in the relevant repository.

For substantial architectural changes, open an issue or discussion before submitting a pull request.

## Security

Please do not disclose suspected security vulnerabilities through public issues.

Follow the security-reporting instructions in the repository’s `SECURITY.md` file. When available, use GitHub’s private vulnerability-reporting feature.

Our security documentation aims to distinguish clearly between:

* implemented protections;
* security assumptions;
* known limitations;
* features under development;
* properties that have been independently audited;
* properties that have not yet been formally verified.
